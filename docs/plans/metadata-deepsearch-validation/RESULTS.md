## 4. 发现的设计问题

1. **搜索质量先于长上下文。** Kozame 的假名词典结果和 Nichijou 的漫画周边页面都不支持目标；增加正文长度无益。应先筛身份和页面类型，再花读页预算。
2. **有引用不代表有证明。** 字符串校验只能拒绝捏造引文，不能判断它是否支持 OAD 集数、发行地区或版本。新护栏测试故意演示：用“one OAD episode”的真实引文回答22，结构校验仍可能通过，必须增加语义验证。
3. **摘要不能自动升级为权威正文。** URL 指向官网也不保证摘要完整准确；正文读取失败、镜像转载、首发/再版应有不同证据等级。
4. **特典计数对象必须先定义。** 一部 OAD、OAD 内部多话、BD 短片、NCOP/NCED 不同。后续 schema 必须输出带类型的条目清单，然后按规则计数。
5. **验收目标不能漂移。** Shazam 的 US 日期是前瞻语义对照，不能虚增对当前 year 门禁的提升；Joker 是已有正确图的对照，不能报告成新识别。
6. **重构判据必须同时比较简单方案。** 若定向摘要问答已足够，不应为了“DeepSearch”命名增加自主循环和成本。

## 5. 决策

**整体重构：NO-GO（证据不足，不是证明该方向无效）。**

可以继续隔离原型验证，但必须先恢复可用模型服务、完成同证据的 B/C 三轮比较，再添加来源选择＋有界追加检索的 D 组。只有 D 相对更便宜方案稳定增加可自动接受的真实缺口、无范围误填，并在留出集和生产入口离线回放中成立，才进入 `PLAN.md` 的灰度实施阶段。
