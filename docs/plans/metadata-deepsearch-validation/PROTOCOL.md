# DeepSearch 困难样本验证协议

状态：隔离探索实验；不修改生产管线，不更新 corpus 的 confirmed 答案。

## 问题与比较组

目标不是证明模型会填 JSON，而是判断有证据的字段补全能否减少原管线的缺口，以及读取正文是否优于更便宜的定向摘要问答。

- A：现有 `UnifiedMetadataAgent.process_title_only`，使用资源原频道主源，保留生产 fallback。每个样本执行一次，记录原始返回与 HTTP 证据。该入口不落库，不验证队列和自动派发。
- B：为场景编制明确范围的问题，wigolo 搜索两次，仅给模型搜索摘要。
- C：复用 B 的完全相同搜索结果，额外读取排名前五个不同页面；不成功的页面不伪造正文。B/C 相同模型、temperature=0.1、字段 schema、每组 3 轮。

C 是 DeepSearch 的最小取证组件实验（定向多查询＋页面阅读＋有据回答），不是完整的自主多跳 Agent。人工编制的问题模板不等于系统已能自主定位所有缺口；正文排名截取也不是已实现的权威来源选择器。

## 样本与防泄漏

从固定的 1,372 条资源快照中有目的地挑选 8 个真实困难样本，覆盖特典、缺日期、版本身份、错误主源分类、多季对照和总集数陷阱。选样不是随机，不能外推全库准确率。

`cases.json` 固定资源 UUID、原始标题、torrent 清单、场景范围与问题。`snapshot_candidate_not_gold` 只说明生产现状，绝不输入 B/C 模型，也不能直接当作正确答案。查询由研究者制定，可能带有领域知识提示（例如发行口径），这会使实验比全自动场景容易，报告必须披露。

源响应只收集一次并冻结，随后三轮仅调用本机真实 LLM；B/C 不会在不同轮次重新搜索。原流程 A 单独联网采集，可能受到不同源/时间/网络可用性的影响；不能把 A 的基础设施故障当成模型能力差距。

独立审查者先查看问题和冻结证据，不看模型回答，再确定字段真值或证据不足。重点检查正文是否直接支持日期的版本/地区语义、是否确实存在完整目录，以及多个页面是否只是同一来源的转载。

## 计分口径

以字段为单位区分：

1. 值正确且证据/范围有效，可接受。
2. 值看似正确，但引用、来源质量或完整性不足，不计自动补全。
3. 错误值或错误范围，计错误自动回答。
4. 主动未知/冲突，不计错误补全，但不增加覆盖率。
5. 超时、HTTP/JSON 失败，计执行失败，不能等同于未找到。

`validate_claims` 只校验 schema 基本形态与引文确实出现，不具备蕴含判断或来源质量判断。它的通过率不等于事实正确率。完整正确率必须来自独立审核，审核未完成的字段单列，不能塞入成功分子。

每个字段报告三轮一致性；耗时和 token 用量分别报告。A 的作品结果只比较语义相同的字段：正片集数不能用来回答 OAD 集数，原电影日期不能用来回答解说版日期。

## 是否进入整体重构

本轮可支持原型/局部适配器的可行性判断。整体重构需同时满足：

- 相对非故障的现有路径，在至少三类困难场景中稳定新增可接受字段；不是只有 JSON 更完整。
- 相对 B，正文/追加取证有明确增益，足以解释额外延迟与成本；若 B 已同样有效，优先实现较简单方案。
- 没有错误自动应用的身份、季范围、特典范围或版本日期；错误样本必须被拒答/冲突策略挡住。
- 更大、未参与调参的留出集复验，并跑通已有真实 pipeline 的门禁→补齐→跨水位线定向派发。当前 8 个探索样本和 title-only 基线不能证明这一点。

不满足则输出 no-go/conditional-go 和具体补实验项，不启动整体重构。不以搜索命中数、填充率、三次相同回答替代上述条件。
