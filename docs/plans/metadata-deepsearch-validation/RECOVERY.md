## 3. 两个必须修复的失败模式

### 3.1 真实字符串、错误表格归属

`runs-recovery-v1/shazam-date-pages-{1,2,3}.json` 全部引用 TMDB 的以下连续片段：

```text
2019年04月05日
12A
劇場公開
アメリカ合衆国
```

冻结页面中，前三行属于**爱尔兰**，最后一行是下一节美国的标题。美国自己的正确记录位于其标题之后，评级为 PG-13。日期恰好一致，掩盖了关联错误。C 三轮均通过字符串检查，但都把相邻行误当美国记录。

因此，不能把这个案例称为“正文提高证据质量”。读页需要保留 section/table 的父子和行关系，引用必须包含结构定位；验证器应核验“地区＋发行类型＋日期”的同一行绑定，而非连续字符串包含。

### 3.2 第三方被说成官方，且稳定重复

Zeztz 的 B 三轮和 C 前两轮用博客的 Case50、另一站的“约50话”填入确定总数，并在解释中多次声称是官方日程。只有 B 第二轮因额外引文错误被现有校验拦住，剩余 **4 次错误证据补全仍通过结构校验**。

C 第三轮返回未知，但其理由又把官方页面的 Last Case 与相邻 Case49 当成同一条记录。它在填值上安全，并不代表推理链已正确。此处需页面来源分类、官方枚举闭合证明和结构化条目抽取，不能用多数投票解决。

另有 Kozame 的 `⼦/子` 等 Unicode 字形差异造成精确引文失败。可评估有界 Unicode 规范化或改用 evidence_id＋原文 span，但必须保留原始文本；不能以模糊匹配放宽来掩盖上面两类真实错误。

## 5. 决策与方案修订

**完成本轮实验，NO-GO 整体重构；不再以“等待模型恢复”为阻塞原因。**

1. 有一个稳定的新补全字段和多类有用线索，支持继续做隔离研究，但未达到协议要求的至少三类安全增益。
2. C 相对 B 没有新增可接受字段，额外正文还有表格误绑定风险；不支持直接建设更重的自主循环。
3. 当前 verifier 放过错误来源/范围证明；即使值和引用字符串正确，也不能进入自动应用。
4. 下一轮 D 只验证具体增量：身份矛盾触发、来源筛选、保留表格结构、针对缺口追加查询。新增证据另行冻结，不能与本轮 B/C 直接混作同条件收益。
5. 先从简单定向问答＋严格 verifier 竞争基线做起。D 达标后才进行留出集和真实门禁→补齐→定向派发验收；本轮不执行生产整体重构。

数据验证评级：**可附限制分享（Share with caveats）**。执行完整性、数值统计和关键证据错误已核验；小样本、人工问题提示、临时 oracle、单次 A、共享服务负载、未覆盖实际落库/队列仍是必需披露的限制。
