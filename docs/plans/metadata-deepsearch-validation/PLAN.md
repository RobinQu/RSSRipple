# 缺口驱动 Metadata DeepSearch 完整方案

> 提案，不是已实施的权威业务契约。当前验证结论为 NO-GO 整体重构；通过下列准入条件后才修改 `docs/design/` 对应领域及生产实现。现行“web fallback 仅补身份”规则保持不变。

2026-09-06 更新：固定样本的 A 与 B/C 三轮已完成，见 [RECOVERY.md](RECOVERY.md)。正文没有带来额外可接受字段，并暴露表格错绑定与第三方来源被说成官方的问题。后续优先验证身份矛盾检测、结构化引用和来源核验，不启动生产重构。

## 1. 目标与非目标

目标：在作品身份与字段语义明确的条件下，用可追溯的网页事实补齐确定性解析/主源未覆盖的真实缺口，减少 Channel 待确认和人工重跑。

非目标：替换所有主源、让 LLM 猜满必选项、提高表面填充率、覆盖人工编辑、让联网动作直接修改作品关系、用搜索结论猜测 torrent 内容。

衡量最终效果的是“正确且有据地从不可派发变为可派发”，不是找到几个链接或返回多少字段。

## 2. 当前架构与接入位置

现有相关模块：

- `required_fields.py` / `resource_confirmation.py`：字段适用性和真实门禁，继续作为唯一判定源。
- `metadata_agent.py`：主源搜索；`metadata_web_fallback.py`：未命中后的身份兜底。
- `metadata_source_registry.py`：系列/季/电影身份粒度；禁止新增一个可绕过注册表的自由文本身份系统。
- `metadata_service.py` / `metadata_repository.py`：现有 upsert、人工编辑保护、季集修正。
- `fetch_service.py`：抓取与 backfill；`job_handlers.py`：Agent 定向/增量处理。

建议新增独立的研究协调层，不把循环逻辑继续堆入现有大文件：

```text
原始资源 → 确定性解析 / torrent → 主源 / 身份 fallback → 正常落库
                                                     ↓
                                             统一就绪检查
                                              ↓ 缺口仍存在
                                          ResearchRequest
                                              ↓ 后台有界任务
                                   规划 → 搜索 → 读页 → 核验证据
                                              ↓
                                      ClaimPatch（不直接写库）
                                              ↓ 乐观并发校验
                          现有保护式写回 → 统一收敛 → 就绪状态变化
                                              ↓ commit
                                     持久化修复事件 → 定向 Agent
```

原主源找到作品但缺字段，也可进入研究；不局限于 `found=false`。主源临时故障与真实缺口分开：故障优先重试，不立即以弱源替代既有权威数据。

## 3. ResearchRequest：从必选字段编译任务

输入由程序构建：

| 属性 | 内容 |
|---|---|
| target | work/collection 身份袋、作品类型、明确 season_number、原始标题与可信别名 |
| scope | 季/电影/特典类别、地区、发行方式、精度、统计截止时间 |
| gaps | 门禁给出的缺失字段及依赖；只包含适用于当前资源形态的项 |
| existing | 当前值与来源、人工保护字段、版本 hash；不能把旧值伪装成独立证据 |
| local_evidence | torrent 路径/大小、已有 assignments，作为包内内容证据，不当作品目录 |
| policy | 允许源、最大请求/读页/token/耗时预算、允许写入的字段集合 |

先按字段分流：

- 作品事实：日期、动漫媒介、别名、已定义范围的剧集目录 → 可研究。
- 资源事实：分辨率、编码、字幕组、实际文件覆盖 → 本地发布/torrent/探测，网页不作为权威替代。
- 结构关系：作品 FK、合集成员、season_number → 身份层与应用约束处理，研究只提交身份候选，不自动改成任意图。
- 派生值：year 从已接受的日期派生；batch_seasons/season_ranges 从 links/assignments 派生，不能让模型另填一份。

“所有必选字段”是验收目标，不意味着为每个字段发搜索，也不允许未知值被补成默认数字。身份无法锁定时，先处理身份歧义，禁止在错误作品上继续填字段。

## 4. 问题模板与计数规则

程序提供稳定的场景模板，LLM 只在界限内改写语言/别名/后续问题。

- 日期：`作品身份 + 季/版本 + 地区 + TV首播/视频首发/院线上映/流媒体`，明确不能用漫画发售或再版日期替代。月/年精度单独记录，不把月首占位日呈现为已知精确日期。
- 特典：先列 `item_id/title/kind/episode_number/release_date`，区分 OAD、OVA、BD short、recap、NCOP/NCED、trailer。按明确 `counting_rule` 算总数，绝不把完整 S00 等同于一个 OAD。
- 正片/多季：输出季级目录；系列52集不能写入第一季。缺少某季证据只保持该季未知，不把全系列结果当齐全。
- 完整性：分开 `announced_total_episodes`、`released_episode_count` 和 `last_verified_episode`，附 `as_of`。看到最高编号、连续若干集或“全話配信”不等于已公布总集数。
- 版本身份：RiffTrax、导演剪辑版、重制版等附带版本约束；不能为了得到日期回退到同名原电影。

模板版本进入缓存指纹和验收记录。字段定义改变时必须换任务版本及 oracle，不能拿旧录制假装新问题已验证。

## 5. 有界 DeepSearch 循环

1. 先用已知身份访问主源结构化端点；若直接能拿到目标字段，无需 web/LLM。
2. 规划一到两个高辨识度查询，优先作品原文名与明确范围；避免单字被搜索引擎拆成词典结果。
3. 对命中页先做目标身份、页面类型和来源等级筛选。过滤论坛灌水、下载站、无关漫画页等，不按排名盲读。
4. 读取正文并定位支持目标字段的段落/表格，保存响应时间、最终 URL、正文 hash 和抽取位置。
5. 提取候选事实，检查矛盾、发行口径、条目完整性；尚有真实信息缺口时再规划一次追加查询或跟随关联目录。
6. 证据足够、确认无答案、相互冲突或预算耗尽时停止。没有“为了完成任务再猜一次”的步骤。

初始预算建议（需实验校准）：每作品最多 4 查询、6 页面、3 模型调用、120 秒总截止；全局低并发，按域名限流。预算是硬上限，不是必须花完。重试使用退避，不在数据库事务里等待网络。

本次只测了定向两查询和前五页读取（B/C），**步骤3、5的自主规划/来源筛选尚未实现或验证**。下一轮 D 组应专门测试这些增量，避免将“加长正文”冒充完整 DeepSearch。

## 6. 证据契约与自动接受

一个字段的候选结果至少包含：

```json
{
  "field": "number_of_episodes",
  "status": "unresolved",
  "value": null,
  "scope": {"work_id": "existing-work-id", "season_number": 0, "kind": "OAD"},
  "items": [],
  "counting_rule": "numbered_oad_episodes_only",
  "completeness": "unknown",
  "evidence_ids": [],
  "conflicts": [],
  "auto_apply": false
}
```

证据单独存储：URL、最终 URL、采集时间、内容 hash、片段/位置、publisher、页面类型、与其他证据的来源依赖。镜像或转载应按同源簇计数，不能当多源共识。

接受层由程序执行，不能相信模型给自己的 `auto_apply=true`：

- 字段类型、枚举、真实日期、身份/季粒度和范围全部匹配。
- 引文确实出现只是第一道检查；还要验证引文能推出该值，以及是否有反证。
- 发行方/制作方/播出平台的直接页面优先；结构化目录按字段规则接受。只有摘要、第三方孤证或可能失真的镜像时降级候选，不能静默升级证据等级。
- 总集数要求明确完整目录/公告，不能靠最高编号推断。特殊篇日期不能拿正片兜底日期冒充真实取证结果。
- `unresolved`、`conflicting` 必须保留，不覆盖已确认数据；低证据结果只能展示建议。
- 保留事实可信度和写入安全两个维度；“我相信日期大概对”不代表可以无人审核写库。

当前 `validate_claims` 不具备语义蕴含判断，不能直接作为生产 verifier。

## 7. 身份与来源策略

身份源白名单和事实证据站点分开，但都必须是用户配置允许的策略。频道 `metadata_fallback_sources=[]` 的禁用选择不得被新模块暗中绕过；如果需引入独立事实研究开关，默认关闭并在配置中解释边界。

事实来自官网不意味着官网 URL 能生成新的 WorkExternalId。系列级 id 仍落合集袋，逐季 id 落季作品，主 id creator-wins；不能覆盖主身份或抢占冲突身份。事实补丁默认不允许修改作品的关系图。

网络内容是数据，不是指令。读页执行器必须限制 HTTP(S)、重定向、大小/时间、出站域名/公共地址，禁止携带内部服务凭证、读取内网/metadata IP、本地文件或执行脚本。生产实现需要 DNS 绑定/受控代理等防重绑定机制；本次实验 reader 的 DNS 前检不是生产级 SSRF 防护。

## 8. 缓存、存储与并发

先复用现有 MetadataCache 存储有版本的研究候选与证据摘要，不为探索性原型立即增加多张业务表；大正文按内容 hash 存独立证据对象。上线审计需求确定后，再设计持久 claim/run 结构和迁移。

缓存 key 至少包括：稳定作品身份、季/版本范围、字段集合、字段语义版本、源策略版本、证据时效。模型/prompt 版本写入 provenance；不以 raw_title 唯一决定作品事实缓存。

- 同作品不同资源共享事实研究，避免每集重复搜索；不同来源策略不能互相泄漏结果。
- 缺信息、矛盾、临时网络故障分开缓存。transient 不长期记成 not_found。
- 连载总集数、状态采用较短时效；固定历史日期较长，但仍支持强制刷新。
- 运行结束使用开始时的版本 hash 检查当前作品/人工字段是否已变化；冲突时重新评估，不能覆盖研究期间的人工修订。
- 同作品研究去重用任务状态/租约；任务已运行时的新字段缺口应合并或排后续任务，不能被去重键静默丢弃。

## 9. 写回与派发闭环

网络研究与落库分离。经过 verifier 的补丁统一走既有保护式更新入口，只填允许的字段，尊重 `manually_edited_fields`；自动修订不会打开 override_manual_edits。

随后执行所有路径共用的身份/季集/动漫/文件指派/资源形态收敛，再重新调用 Channel 门禁。不要让缓存命中、标题短路、普通主源、DeepSearch 各有一套略有不同的落库行为。

如果旧资源由不可派发变为可派发：

1. 在提交事实的同一事务里记录可重试的修复事件（复用已有可靠 outbox 能力；若没有，新增最小持久事件表）。
2. commit 后消费事件，按频道 active Agent 批量定向投递 `resource_ids`，绕过但不推进水位线。
3. 队列 dedup 拒绝入队时事件保留并合并重试；必须收到消费确认后才能了结，不能“enqueue 返回 None 就当成功”。
4. 最终下载去重仍由 Agent 执行，不因多次修复创建重复任务。

DeepSearch 不能替代之前发现的季感知标题索引、缓存 batch_scope 往返及修复后派发缺口；这些基础不变量应先补测试并逐项修正。

## 10. 验证方案

分四层，分别报告而不混算：

### L0：证据与程序护栏（离线 CI）

快照 hash、输入不含答案、URL/重定向安全、字段类型、引文存在性、超时/故障熔断、人工字段保护、不改身份、版本冲突、故障报告。现有 `tests/integration/metadata_corpus` 已接入 CI，本轮新增实验契约测试。

### L1：固定证据、真实模型

同证据 B/C 各三轮及逐字段独立审查已完成（RECOVERY.md）。只有四谎 OAD 集数可稳定接受，正文无净新增。下一轮 D 必须逐项测试身份矛盾检测、来源筛选、表格行/章节结构保留及缺口反馈追加检索；记录每次新增证据与问题并另行冻结，避免重复访问外部源影响三轮复现。针对已被原源错误匹配的作品，先停止字段应用并验证身份，不能在错误对象上补字段。

先完成目前 8 例，不把 Shazam 的地区对照或 Joker 已有正确结果算新增生产收益。对低证据值区分“值正确”和“允许自动应用”。

### L2：未参与模板调参的留出集

建议至少 30 个独立作品，覆盖日期、特典、多季、真人/动漫、版本陷阱等至少五类；同作品不同字幕组不冒充独立样本。额外加入冲突、非存在作品、页面不可读、提示注入、人工保护、源白名单禁用等负例。

建议预先固定的试点准入指标：

- 对可研究缺口的“正确且可接受补齐率”相对最佳简单基线提高至少 20 个百分点，且收益覆盖至少三类场景。
- 已自动接受字段 precision ≥98%，身份/季/版本严重错误为零；三轮字段结论一致率 ≥95%。这些是后续目标，不是本轮已达到的指标，小样本零错误也不等于风险为零。
- 不可研究/证据不足负例正确拒答，不能靠填未知提高覆盖。
- P95 总耗时在约定预算内，记录搜索、读页、模型 token 成本；模型故障请求与质量样本分开。

### L3：真实生产入口离线回放

不是只测 title-only 或直接调用 process_resources：在隔离库复现新入库、已有部分图、旧缓存、跨水位线旧资源、队列忙、人工修订竞争。运行实际修复 handler→commit→事件→Agent 定向运行；验证作品/集合/文件指派正确，并且只派发一次。两数据库均通过，Redis/worker 路径另做容器验收。

线上源可用性/漂移 canary 与离线质量 CI 分开；canary 故障不回写 oracle。只有人工/独立证据核验的样本可升级 corpus confirmed。

## 11. 分期实施与回滚

| 阶段 | 交付 | 开始条件 |
|---|---|---|
| P0 隔离验证 | A/B/C 与独立审核已完成；D 原型和留出集仍未验证 | 当前 B/C 未达到增益和安全门槛；不触碰生产 |
| P1 纯适配器 | GapSpec/ClaimPatch、证据存取、预算、verifier，默认仅输出建议 | P0 有明确增益，不是单纯页面存在信息 |
| P2 shadow | 对真实缺口后台研究，只存候选和审计，不应用 | L0/L1/L2 通过，源与成本策略确认 |
| P3 小范围补空 | 仅日期和明确定义 OAD 目录，复用保护式写回和可靠修复事件 | L3 闭环通过，shadow 错误审查通过 |
| P4 扩大或收敛 | 按收益扩字段；删除重复旧分支仅在证明等价后进行 | 无错误自动绑定，成本收益稳定 |

每阶段小 PR，分别更新 `business-logic.md`、`data-models.md`、`api-endpoints.md`、`conventions.md` 等实际涉及的设计文档。不要在同一个 PR 中重写整个 MetadataAgent、数据库模型和所有入库路径。

默认 feature flag 关闭；按频道/字段白名单灰度。关闭后主源与旧身份兜底继续工作。所有自动补丁保存前值/证据/版本以便追踪，回滚只撤回仍等于该补丁且未被人工后续改动的值；任务/作品关系不可做盲目反向删除。

## 12. 当前阻塞和决策记录

已完成选样、源证据收集、8 个恢复后基线、48 个 B/C 三轮请求、84 个字段回答复核及实验护栏。模型故障不再是阻塞；本轮**没有证明正文 DeepSearch 明显优于简单定向摘要方案**，且错误来源/范围仍可能通过当前校验。

因此不启动 P1–P4。后续 P0 的 D 组只验证具体可测增量，尤其是：①found=true 也触发的身份矛盾审查；②同一表格行的地区/日期绑定；③官方与第三方来源不可混称；④问题中已有的真人/动画提示不能算搜索所得证据；⑤拒答不覆盖已有正确字段。D 在独立留出集上达到门槛后才讨论生产适配器和队列集成。
