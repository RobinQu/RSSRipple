# V35 缓存完整键与迁移审查

范围：`metadata-cache-title-z-source.json` 中相对 V34 的 25 文件。51 项缓存集成与 344 项联合兼容回归已通过；尚未完成正式重基及完整双门禁，因此当前不批准合入。

## 必要性与方案

FileResource 合法 1024 字符标题可被缓存的 VARCHAR(512) 拒绝；单纯扩列仍可能超过 PG 原文复合 btree 限制。录制数据未发现超限，继续按 P2 边界缺口处理。TEXT 保留完整标题，SHA-256/source 作为有限宽度物理键，读和更新再比对原文。普通长标题正常缓存，碰撞仅拒绝命中/覆盖，不能截断或静默缓存另一标题结果。

## 五轴复核

- 正确性：repository 与批量分析共用精确键和 upsert；ORM 插入/改名同步摘要。来源隔离、strip 和 generation 契约保留。原子更新保留 id/created_at、写完整 payload 与 UTC updated_at；陈旧 generation 删除包含观测版本，不误删刷新后同 id 新版本。Turso 写冲突由实际拥有事务的批量 writer 新会话重试，不在 repository 内局部重放别人的事务。
- 可读性：键/写入共用 helper、迁移独立模块，未新增依赖。现有 provider 输出与数据库持久化职责不混合。迁移目录验证与数据复制有明确边界，拒绝未知结构，不通过吞异常、清缓存或放宽原文检查解决。
- 架构：权威模型、业务、升级和测试文档同步。PG 保留现有 advisory/DDL 事务；Turso 使用显式普通事务，不在 CONCURRENT 事务做 DDL。与 V33 搜索、V32 UTC、V34 关键列迁移共存已实际联合验证。新 cache 表与旧库升级均验证。
- 安全/数据保护：实际 schema 检查包括受管列、键、索引、引用、trigger、默认值、排序规则与生成列；未知定义拒绝。标题与 payload 参数绑定，DDL 名称来自固定内部集合。旧行逐字段保留；回填冲突整体回滚，不自动删除。失败阶段既有红测保留，特别是自定义默认值和排序规则遗漏均先复现后修复。
- 性能：定长摘要避免原文 btree 大键；旧数据每批最多 100 行，有 ID 游标，不一次加载全表。PG ALTER 与回填仍持表锁；Turso 重建需临时空间，生产时长/空间未测，须停旧 writer、备份和维护窗口。每次启动目录检查会遍历当前 schema 的表及 FK，成本随表数增长；不是按业务行数无界扫描。已升级结构不重复回填。

## 证据边界和剩余条件

固定 SHA 录制标题配明确合成的长文本、身份、历史规模、来源结果和故障。实际双库集成覆盖完整标题矩阵、碰撞、来源隔离、修改/回滚、新旧库启动、PG 并发启动、批量 writer 真实冲突恢复，以及真实 MetadataAgent 的确定性未命中和成功作品关联。来源检索/LLM 输出为边界替身，不声称在线模型准确性或生产已有长标题损坏。

PG 旧连接的 prepared statement 在 ALTER 后可失效，必须重建连接，不保证无中断在线升级。Turso 单进程文件独占约束不变。列出的 schema 反例不是所有可能自定义 DDL 的穷尽证明；发现非受管定义应继续拒绝并人工审查。没有以本轮新增摘要重写旧业务内容。

最终批准还需基于 V34 最终验收主干正式重基、全输入冻结、完整单元/API ≥95% 和隔离集成 ≥85%、零失败，并核对跳过基线、实际退出、导出、清理与最终 Git 对象范围。当前 344 项联合回归不能替代这些门禁。
