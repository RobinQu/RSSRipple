# V34 AgentRun 生命周期合入审查

范围：`agent-run-lifecycle-ah-source.json` 的 28 个非计划文件，另含已单列的历史探针导入格式维护。基线 main 5422410，6785 输入冻结。当前为审查记录，完整 ai/aj 门禁尚在运行，未批准合入。

## 必要性与方案

真实双库 handler 普通异常与进程退出可留下 running 历史，属于已复现的 P2 异常恢复缺口。普通 try/finally 不能处理强杀，单凭历史年龄无法证明执行者已失权。方案以数据库时钟租约为执行许可，短事务条件收尾/回收；无租约旧历史由停写备份后的明确快照审核处理。保持 B9 请求确认和 B7 消费语义，不声称可以撤销已发生的外部副作用。

## 五轴审查

- 正确性：租约和 running 历史在第一事务一起持久化；处理期间独立短事务续约，关键路径同时检查队列与数据库执行权。期限来自数据库 UTC epoch，过期 token 不可续约。完成以条件 DELETE RETURNING 取得执行权，在同一事务写历史、确认/推迟请求及消费进度；回滚恢复租约。旧运行摘要更新要求 Agent.current_run_token 匹配，消费水位不倒退。回收再次检查过期条件，历史及摘要原子更新，保留计数并明确可能不完整。
- 可读性：租约原语、心跳范围和最终收尾分属三个职责明确的模块，handler 保留开始/处理/收尾阶段。ContextVar 只表示当前 Agent 执行身份，直接 API 无该 scope 时仍保留原队列检查。离线审核脚本不混入在线调度。
- 架构：沿用 committed_session/retry_on_lock 和既有队列 ownership 协议，不新增依赖。V30 显式 works 加载与 V32 UTC 契约保留；current_run_token 为必须成功的轻迁移，新租约表由 ORM 创建。scheduler 每 30 秒直接运行回收，不排在可能满载的任务队列之后。
- 安全：所有权未知时关键路径拒绝继续。错误历史只记录异常类型，B9 延迟请求沿用原诊断契约。离线 apply 要求显式 fingerprint 与所选 IDs、停写/备份标志，PG 锁历史/租约表，Turso 使用普通写事务；先检查整批完整快照再写，漂移拒绝。报告独占创建，不能覆盖已有文件。不自动处置无租约历史。
- 性能：租约独立表，按 expiry/id 索引有界回收默认 100/最多 1000；不扫描整张历史判死。心跳默认 10 秒、租约 30 秒，只更新执行状态；每个关键 checkpoint 增加一次按 run/token 查询，这是失权保护成本。审核导出有 ID 游标和上限，apply 最多 1000。慢外部工作不进入最终收尾重试。

## 证据及边界

先前 ae/ag 覆盖生命周期、B9/B7、加载、迁移、UTC；独立 RedisQueue 强杀/暂停接管证明相同 job 的不同执行 token 不能回写旧状态。测试中的资源标题来自固定 SHA 录制数据，身份/故障/竞争时序明确合成。

实际 scheduler、主动 PostgreSQL/Redis TCP 断连、重复取消时等待已启动心跳 DB 操作结束、旧 schema 关键列失败、离线 CLI 两后端审核与漂移拒绝均有原始证据。不将主动断连接受结果外推任意网络黑洞或永久驱动阻塞；不把独立 RedisQueue consumer 描述成完整 app.worker 启动。心跳清理可能等待已启动 DB 操作结束，这是已记录的原生驱动约束。

最终验收仍需 ai 单元/API ≥95%、aj 集成 ≥85%、零失败，核对每项跳过与 V33 基线、冻结输入、实际退出、覆盖率导出及项目清理，再复核实际提交范围和全部非计划 Git 内容。未以专项通过替代这些门禁。
