## 方案论证

只改成 rename 可以防止新半写文件，却无法区分已有截断缓存（即使 JPEG 魔数仍完整）和成功缓存。因此候选组合使用同目录暂存原子发布及长度/SHA-256 收据，不增加解码库依赖。收据只证明 HTTP 响应字节完整保存，不能宣称完成图片解码或内容安全检查；现有格式嗅探保持原策略。

- 读取命中要求收据版本、字节数、完整 SHA-256 一致；缺失/损坏/旧缓存重新获取。成功替换前保留旧文件，不因未验证就先删除。
- 先完整写图片和收据暂存，flush/fsync 后依次原子替换。两次替换之间中断只造成下次未命中；最终图片路径不承载本次半成品。
- 全部磁盘操作与 HTTP 放在线程内。公共函数参数、URL 格式、支持的嗅探格式不变。
- 收据不保存原 URL/凭证。`/posters/...` 本地 URL 保持原先透传；未知历史远端不能由哈希反推，需要元数据刷新恢复来源。
- 普通错误清理本次临时文件；崩溃留下的隐藏暂存不命中缓存，不按 glob 删除其他可能在途的写入。自动回收此类未知暂存不属于已验证能力。
- 同 URL 并发发布可能产生短暂收据不一致，严格作为缓存未命中处理。没有凭文件存在而降级接受的分支。
