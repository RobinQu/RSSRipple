# 前端路由与页面设计

> **移动端适配**：视口 < lg（992px）时侧边栏替换为顶部栏 + 汉堡菜单抽屉导航（`MobileNav`），内容区 padding 缩小；各页头部/工具栏（标题 + 操作按钮）统一 flex-wrap 换行，详情页标题 `flex: 1 1 200px` 防挤压；剧集/电影/音频详情页的海报 + Descriptions 窄屏换行为上下堆叠；统计卡片栅格使用 `xs={24} sm={8/12}`；宽抽屉（如运行匹配资源 680px）< 768px 时退化为 100% 宽。**antd 表格移动端堆叠**：表格加 `className="stack-table"` 并用 `withMobileLabels()`（`utils/table.ts`，把列标题注入 td 的 `data-label`）包裹 columns，< 760px 时每行变为卡片式垂直堆叠（每格一行、前置列名标签，空单元格隐藏，文本格可多行换行）；已接入：Agent 列表、Agent 详情任务表/运行记录表、频道列表、下载器列表、下载器详情双表、剧集/电影/音频详情资源表。

频道详情平铺资源行的作品分类标签区除“剧集/电影”“合集”外，在资源曾创建过任意下载任务（不区分 Agent/手动来源及任务状态）时显示“已下载”。

### 关键交互说明

- **认证流程**：`/login` 位于 `AppLayout`（侧边栏布局）之外，认证前不渲染侧边栏；输入 6 位 TOTP 验证码自动提交 `POST /auth/otp`，成功签发 HttpOnly Cookie `rssripple_auth`（30 天）并整页重载 `/`。API client 统一处理 401（当前路径非 `/login` 时跳转 `/login`，登录页自身的失败 OTP 401 就地展示）。侧边栏底部提供"退出登录"按钮（`POST /auth/logout` 后跳转 `/login`）。

- **Filter DSL 编辑器**：前端使用树形 UI，支持 AND/OR 节点嵌套、添加/删除/拖拽条件节点；每个字段条件提供字段名下拉（**语义分组**六类：发布信息 / 集数信息 / 标题信息 / 作品类型 / 剧集作品 / 电影作品，`useFieldOptions` 手维护分组）、operator 下拉（根据字段类型动态展示可用 operator）、value 输入。字段下拉可被频道 `required_metadata_fields` 门控（`allowedFields` prop，仅 AgentForm/AgentDetail/WorkSelector/FilterSummaryModal 的过滤 DSL 传入；偏好选择 PreferenceListEditor 与 OrganizeRuleFormModal 不传入=不限制）；现存条件引用了门控外字段时，该条件旁显示警告图标（提示依赖非必填字段、保存将被后端拒绝）。所有字段类型的 operator 列表都包含 `is_empty`/`is_not_empty`（"为空/不为空"），选中后不渲染 value 输入；取值操作符的 value 留空时输入框标红，且保存前（AgentForm 提交、Agent 详情全局过滤/作品订阅保存）统一用 `findInvalidConditions` 拦截并提示——空值条件禁止保存（后端创建/更新接口同样 422 校验全局 `filter_config` 与每个作品的 `filter_overrides`）。删光条件后的空树（`{combinator, conditions: []}`）在所有保存/预览 payload 中一律经 `nullIfEmptyFilter` 归一化为 `null`（即"无过滤"），后端不接受空 conditions 列表。字符串字段 + `eq/ne/contains/fuzzy` 会通过 `GET /channels/{id}/field-values?field=&q=` 提供服务端 top-10 频率排序 + 前缀搜索的候选值下拉（保留自由输入），列表字段（`subtitle_langs`）预填 BCP-47 语言代码，genre 字段（`series.genre`/`movie.genre`，与 `series.rating` 同组）从封闭 TMDB 27 类下拉选择（label 走 `genre.*` i18n 中文显示、值存英文 canonical 名，无自由输入），布尔字段（`is_batch`，及 work 字段组新增的三态 `series.is_anime`/`movie.is_anime`）用 `是/否` Select，枚举字段（`episode_confidence` 与 `content_type`）从固定值下拉选择（集号可信度 `raw/reconciled/ambiguous/manual`；作品类型 `tv/movie/audio`，`describeFilter` 摘要经 `filter.enumValue_*` 本地化）。提供"测试"按钮调用 `/agents/{id}/test-filters` 实时预览当前频道资源匹配情况。
- **Agent 详情过滤条件合并展示**：第一个 Tab（订阅作品管理）顶部以只读 Tag 形式展示全局 `filter_config`（经 `describeCondition` 渲染为人类可读文本）；每个作品的设置折叠面板内（`WorkSelector`，接收 `globalFilter` prop）在作品自身 `filter_overrides` 编辑器上方展示"与全局过滤合并后"的全局条件，让用户看到生效的完整过滤 = 全局 AND 作品覆盖。
- **Channel 详情多选生成规则**：用户在资源表格勾选若干符合预期的资源，点击"生成过滤规则"，前端将选中 resource_ids 发送到后端 `summarize-filters`，后端按 Agent 规则结构返回建议：选中资源链接的作品列表（作品订阅）、全部资源 ≥80% 同值字段的全局条件、以及每个作品内部 ≥80% 同值的差异化条件（详见 api-endpoints.md）。**弹窗加载时即把生成的全局共性条件按 AND 折叠进每个作品的差异化条件**——生成的规则只存在于作品维度（单个作品时全部条件都落在该作品上），全局规则区块置空、仅供人工编辑。弹窗内：顶部按作品展示订阅卡片（poster/标题/资源数 + 可编辑的作品级 FilterBuilder），下方为仅人工编辑的全局 FilterBuilder；"新建Agent"与"应用到已有 Agent"两种模式行为一致：作品级规则按键合并/追加订阅（已订阅同作品则 AND 合并其 filter_overrides），只有用户人工添加的全局规则才会写入（新建）或按 AND 合并进（应用）目标 Agent 的 `filter_config`；"新建Agent"模式名称预填 `agent-{channel_name}-{YYYY-MM-DD}`，确认后带 filter_config + works 预填跳转新建表单。所选资源全部未关联作品时，生成的共性条件无作品可依附会被丢弃（仍可人工添加全局规则）。
- **资源详情抽屉**：Channel 详情点击资源行打开右侧抽屉，展示 poster（若有）、metadata（作品名、集数）、解析字段明细、磁力链接复制按钮；抽屉内嵌**文件清单区块**（`ResourceFilesView`，数据走 `GET /resources/{id}/files` 的 torrent 文件清单树）。**「元数据」与「解析字段」两区块均为纯只读**（旧的内联编辑、修正匹配铅笔按钮与 TV 单集快速修正 Popover 已移除，编辑统一收敛到底部向导）；合集资源的解析字段区块追加**只读逐季集数范围 Tag 行**；`is_batch=true` 且存在文件级映射时展示**「作品 ↔ 文件关联」区块**——按作品分组（类型 Tag + 标题 + 文件数），TV 作品下按季分桶，文件行显示路径/集号区间/体积，末尾列出未分配文件（最多 20 条折叠）；数据来自详情端点的 `file_assignments` + files 端点清单。**footer 操作栏**：「编辑」（打开三步统一向导 Modal）+「创建下载任务」。
- **五步统一编辑向导（ResourceEditWizard）**：仪表盘「文件资源元数据确认」、频道详情资源行「修订」与抽屉 footer「编辑」共用同一向导（`ResourceCorrectionModal` 仅作薄壳，打开时自行拉取资源详情与文件清单；保存失败保持弹窗开启）。**① 作品关联**——是否合集 Switch + 作品 chips 增删（「添加作品」弹窗双 Tab：本地库搜索选择 series/movies API / 在线元数据搜索确认创建走 metadata search+link）；音频作品资源锁定关联编辑并提示仅可编辑通用字段；底部实时预览自动推导的 batch_scope。**② 文件映射**（左右双栏）——左栏为可选中作品列表（类型+标题+已映射计数、行内删除、底部添加按钮），右栏为全量文件列表：复选框支持 **Shift 范围选择**，工具栏提供 季参数 InputNumber + 「加入所选作品」（文件名/目录名解析出的 season 优先、参数兜底；episode 由确定性路径解析预填，未映射行显示 S/E 识别 Tag）+「移除映射」；每行对已映射 TV 文件内联 S/E1/E2 微调输入；「重新解析」调 `POST /analyze-batch`（deterministic 层无需 LLM 即返回逐文件季/集解析与簇提示，LLM works 块按归一化标题自动落位并 toast 汇总）；非合集分支仍为 TV 单集三字段/Movie 提示。**③ 作品集关联**——独立步骤：搜索已有作品集（服务端 search 下拉）或就地创建（名称输入 → `POST /collections` 并自动挂载），非合集资源提示跳过。**④ 通用字段**——7 个文本字段全部为 AutoComplete 下拉（选项来自 `GET /channels/{id}/field-values` 按频道枚举值频次排序）且允许自由文本；subtitle_langs tags 多选不变。**⑤ 确认页**——汇总展示全部变更（合集范围 old→new、作品增删、文件映射变更清单（path + 目标作品/季/集）、单集字段差量、通用字段差量、作品集变更），用户点击「确认」才执行 `PUT /resources/{id}/associations` 保存；无任何差异时提示并不关闭数据。
- **待决策卡片**：Dashboard 和 Agent 详情的待决策项展示候选资源的核心字段对比（字幕组/分辨率/编码/体积/发布时间），每个候选在格式化标题之外**额外展示原始标题**（`title_raw`，带「原始标题」前缀、单行省略 + 悬浮全文，仅当与格式化标题不同时显示，便于人工按字幕组/季集标记判断）；llm_enabled 时展示 LLM 推荐理由并高亮 `llm_picked_resource_id` 对应行；点击候选选中，点击"确认"提交。每条决策可点"AI 自动处理"（`POST /decisions/{id}/ai-pick`）一键采纳 LLM 选择；列表支持多选后批量 skip / AI 处理（`POST /agents/{id}/decisions/batch`）。集号/季号不确定类决策（所有候选 `episode_confidence === 'ambiguous'`）不展示候选对比，改为逐候选内联修正：`季号` + `季内集号` + `绝对集号（可选）` 三个 InputNumber（预填资源现值，只回传用户改过的字段，走 `PATCH /resources/{id}/episode`），保存后 `episode_confidence="manual"` 并触发定向 Agent 重跑。候选行另可打开文件清单 Drawer 与解析修订 Modal（`ResourceCorrectionModal`，同资源详情抽屉入口）。

- **文件清单 Drawer（ResourceFilesDrawer）**：按目录层级渲染 torrent 文件清单树（`GET /resources/{id}/files`），统一入口于：频道详情资源抽屉（内联区块）与资源行操作、作品详情（剧集/电影）资源表操作列、Dashboard/AgentDetail 待决策候选行、AgentDetail 运行记录详情的资源条目（处于待决策的条目另带「待决策」warning Tag，数据来自 runs 端点 `matched_resources[].pending_decision`；运行记录操作列按钮按 `status === 'pending_decisions'` 显示「待决策」文案）。
- **资源排障与向导适配**：资源详情抽屉在解析字段中展示资源唯一 ID（等宽文本 + 一键复制）；「修订解析字段」向导在标题下方固定展示当前文件资源的原始标题与资源 ID，防止多窗口操作时混淆目标。五步向导桌面端使用接近视口宽度的工作区、固定步骤栏和操作栏，中部独立滚动；文件映射双栏填满中部剩余高度，候选清单自适应占满右栏而非使用固定最大高度；窄屏为全屏并将双栏折叠为单栏。文件候选支持鼠标左键拖选、触屏 swipe 与 Shift 起止范围选择；加入作品后立即从候选池移除。进入文件关联步骤时若详情已有有效文件映射则直接复用，不自动重复解析；仅用户点击「重新解析」时重跑。重新解析期间隐藏作品/文件操作区并锁定上一步/下一步，展示 SSE 状态与 LLM 增量输出，结束后自动回到映射编辑态；确定性 S/E 结果始终保留，单一 TV 作品时直接预填逐文件映射，LLM 建议失败不影响确定性结果。确认页只展示真实变化的合集范围，文件映射变化不截断、由向导整体滚动完整展示。
- **Drawer 主题可读性**：元数据作品卡片必须使用 `--rr-success-soft` / `--rr-success-border` 语义背景边框，并以 `--rr-text` / `--rr-text-secondary` 显式承载主次文字；禁止直接使用由深色 success seed 推导的 Ant Design `colorSuccessBg`，确保 light/dark 两种模式均有稳定对比度。
- Drawer 的资源 ID/下载链接复制必须兼容非安全 HTTP 来源：安全上下文使用 Clipboard API；非安全 HTTP 来源必须在点击事件的同步调用栈内执行临时 textarea + `execCommand('copy')` 回退，并仅在命令成功且页面实际处理了 `copy` 事件、写入 `clipboardData` 时提示成功，禁止只凭 `execCommand` 返回值报告成功。文件向导自动分析请求使用缓存，只有用户点击「重新解析」发送 `force=true`。
- 频道详情页「手动抓取」必须先弹出确认对话框；默认只抓新条目，用户显式勾选「重新抓取所有条目的 metadata」后才向 `/channels/{id}/fetch` 发送 `force=true`。关闭或取消对话框不得触发抓取。
- 文件映射应用 LLM 结果时优先使用服务端校验的 `candidate_key`（`series|movie:<UUID>`）直接匹配向导作品；仅对无 candidate_key 的旧缓存使用展示标题归一化回退，不能再因 original_title 与英文/中文别名不同而丢弃整组映射。
